## 0. Текущий статус проекта

**Дизайн мобильной версии полностью готов и принят заказчиком («фиксируем»).**

Что уже сделано:
- Мобильная PWA — визуальная копия официального приложения MetaTrader 5 (iOS, светлая тема), пиксель-в-пиксель по скриншотам заказчика (много итераций сверки).
- Все страницы: Авторизация, Котировки, Чарт (с индикаторами Ишимоку 9/26/52 + Фракталы, посчитаны реально от мок-свечей), Торговля, История (3 вкладки, сортировка, итоги Депозит/Снятие/Прибыль/CFD/Своп/Комиссия/Баланс), Выбор периода, Детали сделки, Редактирование сделки, Настройки, Админ-панель.

- Все данные — моки (JSON/TS-модули), редактирование сделок работает локально (editStore).
- Стек: React 19 + TypeScript + Vite 7 + Tailwind 3.4 + lightweight-charts 5 + react-router 7.

**Артефакты дизайна (передать исполнителю вместе с этим планом):**

**Дальше — этап «оживления»:** заменить моки реальными данными (backend + MT5), добавить страницу выбора платформы и ПК-версию, подключить домен и задеплоить.

## 1. Новый пользовательский флоу (от заказчика, 08.09.2026)

```
Сайт заказчика (существующий)
   └── страница «Мой кабинет»
         └── кнопка «Скачать мобильную версию МТ5»
               └── НОВАЯ ВКЛАДКА: страница выбора платформы
                     ├── «Веб-версия для телефона» → мобильная PWA (ГОТОВА, текущий проект)
                     └── «Веб-версия для ПК»      → ПК-версия (НОВЫЙ сайт, 2 страницы)
```

Требования к флоу:
1. На сайте заказчика, в разделе «Мой кабинет», размещается кнопка «Скачать мобильную версию МТ5».
2. Кнопка открывает **в новой вкладке браузера** отдельную страницу выбора платформы.
3. На странице выбора — два варианта: веб-версия для телефона и веб-версия для ПК.
4. «Для телефона» → редирект на мобильную PWA (текущий проект).
5. «Для ПК» → редирект на ПК-версию: сайт из **двух страниц** (см. Этап 7; какие именно 2 страницы — предположительно Торговля и История, **уточнить у заказчика**).

**Домен:** заказчик уже купил домен. На него навешиваем: страницу выбора платформы + обе версии терминала (см. Этап 8).

## 3. Правила работы для исполнителя (Claude)

1. **Дизайн заморожен.** Перед любыми правками читай `DESIGN_SPEC_MT5.md`. Менять стили/раскладку можно только по прямому запросу. При подключении реальных данных верстка не трогается — меняется только источник данных.
2. **Моки не удалять.** Все моки остаются в коде и отключаются флагом (`VITE_DATA_SOURCE=mock|api` в `.env`), чтобы можно было мгновенно вернуться к демо-режиму.
3. **Коммит после каждого завершённого пункта** чек-листа.
4. **Проверка после каждого этапа:** открыть страницу и сверить со скриншотами из `design/` — визуальных отличий быть не должно (кроме самих значений данных).
5. Сервис-воркер: текущий `public/sw.js` — cache-first, агрессивно кэширует. При деплое реализовать нормальную стратегию версионирования (network-first для HTML, versioned cache для ассетов), иначе пользователи не будут получать обновления.
6. Логотип MetaTrader 5 — товарный знак, в PWA-иконках используется нейтральный знак. Если заказчик предоставит свой логотип — заменить (5 минут).

### Этап 2 — Backend API (2–3 сессии)
- [ ] **Авторизация:** `POST /api/auth/login` (JWT), мидлвар проверки токена. Единая база пользователей (интеграция с существующей системой заказчика — по готовности доступов, до этого — своя таблица `users`). Демо-режим сохранить.
- [ ] **Счёт:** `GET /api/account/summary` → баланс, средства, маржа, свободная маржа, уровень маржи, плавающая прибыль.
- [ ] **Позиции:** `GET /api/positions` → открытые позиции (символ, тип, объём, цены, своп, прибыль).
- [ ] **История:** `GET /api/history?tab=deals|orders|positions&symbol=&from=&to=&sort=` — фильтры по символу и периоду (сегодня/неделя/месяц/3м/6м/год/custom), сортировка (по умолчанию/символ/тикет/тип/объём/время открытия/время закрытия/прибыль). Итоги: депозит, снятие, прибыль, CFD, своп, комиссия, баланс — с той же логикой видимости строк Снятие/CFD, что сейчас на фронте (за весь период — всегда; за выбранный — если ненулевые).
- [ ] **Редактирование:** `PATCH /api/trades/:id` (прибыль, своп, комиссия, комментарий, время/цена открытия/закрытия) → `is_edited=TRUE`. ВАЖНО: пометка «(изм.)» в UI НЕ выводится (требование заказчика), флаг хранится только в БД.
- [ ] **Котировки:** `GET /api/quotes` + `GET /api/candles?symbol=&timeframe=` через интерфейс `QuoteProvider`:
  - `mock` — текущие моки (разработка);
  - `external` — Yahoo Finance / Alpha Vantage (рабочий режим до появления MT5);
  - `mt5` — из MT5-коннектора (Этап 4).
  - Интервал обновления — из конфига, по умолчанию 5–10 сек (заказчик спрашивал про чаще 30 сек — можно хоть 1 сек, упор в лимиты бесплатного API).
- [ ] **Отчёт:** `GET /api/report?format=html|csv&from=&to=` — генерация торгового отчёта (сейчас на фронте уже есть генерация HTML/CSV — перенести данные из API).
- [ ] **Админ API:** пользователи/роли, лог импортов, ручное редактирование баланса/маржи, настройки автообмена.
- [ ] **Ручная загрузка HTML-отчёта MT5:** `POST /api/upload/report` + парсер `mt5-parser.js`. Не требует доступа к MT5-серверу — нужен только файл отчёта от заказчика. **Запросить файл у заказчика в первую очередь.**

**Результат:** API полностью покрывает потребности обоих фронтов, данные — из БД (наполненной моками/парсером).

## 6. Риски и как их обходим

1. **Нет доступа к MT5** → архитектура с `QuoteProvider` и отдельным коннектором: всё остальное делается и сдаётся без него, MT5 подключается последним без переделок.
2. **Лимиты бесплатных API котировок** → интервал в конфиге; при упоре в лимиты — платный план или переход на котировки MT5.
3. **PWA-кэш** → при деплое заменить стратегию service worker, иначе обновления не доходят до установленных копий.
4. **ПК-версия без уточнённого состава** → не стартовать Этап 7 до подтверждения двух страниц.
5. **Единая авторизация с сайтами заказчика** → если API не дадут, терминал живёт на своей БД пользователей, интеграция — отдельным этапом позже.
