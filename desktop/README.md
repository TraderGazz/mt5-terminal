# desktop/ — ПК-версия

Визуальная основа — прототип, переданный заказчиком через стороннего
разработчика (29.09.2026): обычный HTML/CSS/JS без фреймворка, пять classic
`<script>` с общей областью видимости (`app.js → header.js → sidebar.js →
native.js → interaction.js`, порядок обязателен — поздние файлы
переопределяют функции ранних через приём `const prev=fn; fn=function(){prev();...}`,
см. комментарии в начале каждого файла).

Поверх этих пяти файлов НИЧЕГО не правится — вся интеграция с реальным
бэкендом (тот же backend, что и у мобильной версии) вынесена в `public/live.js`,
подключаемый последним скриптом и использующий тот же приём обёртки. Так
проще принимать будущие обновления дизайна от заказчика без конфликтов.

## Структура

- `index.html`, `login.html` — две страницы (терминал и вход), собираются Vite.
- `public/` — classic-скрипты и стили прототипа + `live.js`/`login.js`.
  Всё, что лежит в `public/`, Vite копирует в `dist/` как есть, не трогая
  (они специально НЕ `type="module"` — модули имели бы отдельную область
  видимости и сломали бы совместный доступ к `state`/`action`/`sim` и т.д.
  между файлами).
- `vite.config.js` — только dev-прокси на `/api`/`/ws` (→ `server/`, порт 4000)
  и multi-page сборка (`index.html` + `login.html`).

## Что реальное, что нет

Реальные данные (через `public/live.js`, контракт идентичен мобильной
версии — `/api/account`, `/api/positions`, `/api/history`, `/api/candles`,
WS-каналы `account`/`positions`/`quote`/`candle:<TF>`):

- Заголовок окна и запись счёта в Навигаторе — реальные номер/ФИО.
- Открытые позиции и закрытая история — реальные (маппятся в формат
  прототипа в `live.js`, см. `mapPosition`/`mapHistoryRow`).
- Свечи и переключение таймфрейма — реальные для M1/M5/M15/M30/H1/H4/D1
  (сервер не отдаёт другие периоды — остальные кнопки/попап у прототипа
  остаются декоративны, просто не перехватываются `live.js`).
- Текущая котировка (WS `quote`) — двигает цену/подпись на графике.

Декоративно (как было задумано в самом прототипе — локальная симуляция,
функциональность не заказывалась): постановка ордеров, SL/TP, рисование
объектов на графике, алерты, журнал, мозаика, Обзор рынка по символам
помимо активного, right-click меню, большая часть пунктов меню/тулбара.
Решение, делать ли что-то из этого реальным — отдельно, по мере обсуждения
с заказчиком.

## Запуск

```
npm run dev:desktop     # Vite dev-сервер :3100 (прокси на :4000)
npm run build           # соберёт client + desktop в их dist/
```

Нужен поднятый `server/` (`npm run dev:server`) и БД (`npm run db:start`).
Вход — обычный логин/пароль (тот же пользователь, что и в мобильной версии
и в админке), токен хранится в `localStorage['mt5pc-token']` — тот же ключ,
что использовала прежняя React-версия, так что уже залогиненные сессии не
слетают.
